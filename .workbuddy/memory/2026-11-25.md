## Casdoor admin approval gate (uncommitted)
- Security decision: Casdoor proves identity, not employment. Every first sign-in / link now creates `crm_casdoor_access_requests` (migration `20261125000000_crm_casdoor_access_requests.sql`) and opens NO Supabase session until a super admin approves. Rejected customers cannot enter CRM even if they have a Casdoor account.
- Pre-filters from `/api/get-account`: default `CASDOOR_ALLOWED_USER_TYPES=normal-user` rejects `guest-user` customers; optional `CASDOOR_ALLOWED_EMAIL_DOMAINS` and `CASDOOR_ALLOWED_ORGANIZATIONS`. Type check fails closed if account endpoint is unavailable. `policy-config.ts` holds these non-secret helpers so they remain unit-testable without `server-only`.
- `provisionCasdoorSession` creates a disabled auth user + pending request but returns no OTP unless an approved request exists; login error params `pending_approval`, `access_rejected`, `domain_not_allowed`, `account_type_not_allowed`, `organization_not_allowed`. Link mode files a request without binding or signing out.

- `/profile` shows pending/rejected/revoked link state; unlink revokes approvals so re-linking requires review again. Existing Casdoor users need one-time re-approval after the migration.

## Casdoor post-logout URL + link failure diagnostics (uncommitted)
- Casdoor rejected `post_logout_redirect_uri=https://oboyacrm.vercel.app/login?signed_out=1` with "redirect URI not in allowed list": its Redirect URL matching is exact and does not accept query strings. Default changed to query-free `${origin}/login`; signed-out notice now carried by a 5-minute first-party `casdoor_signed_out` cookie read by the server-rendered login page and cleared client-side. `.env.example` and docs updated: register `/login` (not `/login?signed_out=1`) in Casdoor.
- The deployed link flow collapsed state/session/token/profile failures into one `casdoor` error. `/callback` now emits `oauth_state`, `oauth_session`, `oauth_token`, `oauth_profile` with localized messages on /login and /profile, and logs the real exception server-side.
- Hardening: flow cookies are set directly on the redirect response (not via the request cookie store), token exchange retries `client_secret_basic` after `client_secret_post`, and `fetchCasdoorProfile` fills missing userinfo claims from the ID token so a Casdoor token format without email no longer aborts linking.
